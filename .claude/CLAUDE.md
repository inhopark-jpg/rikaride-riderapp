# 작업 프로세스

루트 `CLAUDE.md` 가 `@` 로 임포트하므로 매 세션 로드된다. 짧게 유지한다.

## 7단계

| # | 단계 | 하는 일 |
|---|---|---|
| 1 | 이해 | 무엇을 만드는지 한 문장으로 말할 수 있는가. 아니면 질문한다 |
| 2 | 분석 | 입력(Figma URL / 기존 코드 / 토큰)이 실제로 있는지 확인한다 |
| 3 | 탐색 | **`docs/README.md` 표에서 해당 룰북을 찾아 Read 한다.** 기존 컴포넌트도 본다 |
| 4 | 계획 | 아래 산출물을 사용자에게 보고하고 **승인을 받는다** |
| 5 | 실행 | 승인된 계획만 실행한다. 벗어나면 멈추고 다시 보고한다 |
| 6 | 검증 | 빌드·타입체크·스토리 확인. 필요하면 `qa-reporter` 위임 |
| 7 | 완료 | 무엇을 했고 무엇을 안 했는지 사실대로 보고한다 |

### 3단계 — 탐색

- `docs/README.md` 를 Read 한다
- 표에서 지금 작업에 해당하는 행을 찾는다
- 그 행에 적힌 문서를 **전부 Read 한다.** 제목만 보고 내용을 추측하지 않는다
- 두 행에 걸치면 둘 다 읽는다

### 4단계 — 계획 산출물 (전부 필수)

```
1. 읽은 룰북 목록      ← 필수. 해당 없으면 "룰북 해당 없음"
2. 만들 파일 목록
3. 쓸 토큰 목록        ← 실제 토큰 이름. "적절한 색" 같은 말은 계획이 아니다
4. 확신이 없는 부분
```

토큰 이름을 못 적겠으면 계획이 아직 덜 된 것이다. `design-tokens.json` 을 조회하고, 없으면 없다고 보고한다.

## 코드 작성 전 승인 필수

4단계 보고 없이 파일을 만들거나 고치지 않는다. 예외는 사용자가 명시적으로 "바로 해라"라고 한 경우뿐이다.

## 금지사항

| 하지 말 것 | 대신 |
|---|---|
| `src/styles/theme.css` 직접 수정 | `design-tokens.json` 수정 → `npm run tokens:build` |
| 색상·치수 리터럴 (`#fff`, `p-[13px]`) | 토큰 유틸 또는 `var(--...)` |
| primitive 토큰 사용 | semantic 토큰만 |
| 토큰이 없을 때 근사값으로 채우기 | 없다고 보고하고 멈춘다 |
| 룰북 내용을 다른 문서·프롬프트에 복사 | 경로로 참조 |
| 룰북을 승인 없이 수정 | 문제를 발견하면 보고 |
| `design-tokens.json` 에 토큰을 임의 추가 | 보고하고 승인받는다 |
| 룰북 전제와 다른 이름 체계를 억지로 매핑 | 멈추고 보고한다 |
| 룰북을 안 읽고 구조·네이밍을 추측 | 3단계에서 Read |
| 컴포넌트만 만들고 스토리 생략 | 4파일 전부 |

## 충돌 처리

룰북과 `CLAUDE.md` 가 충돌하면 **룰북이 우선**이다. 충돌을 발견하면 작업을 멈추고 사용자에게 보고한다 — 임의로 한쪽을 골라 진행하지 않는다.

## 룰북 편집 프로토콜

룰북(`docs/design-system-rule/*.md`) 은 여러 파일이 서로 §번호로 참조하므로, 한 파일만 보고 판단하면 연쇄 영향을 놓치기 쉽다. **Claude 에게 룰북 수정을 위임할 때** 지켜야 할 순서:

1. **관련 룰북 전부 Read.** 수정 대상뿐 아니라 이 룰북을 §참조로 인용하는 다른 룰북까지 함께 읽는다.
2. **영향받는 섹션 전부 열거.** "이 편집으로 A.md §3, B.md §5, C.md §1이 함께 영향받는다" 식으로 리스트업해 사용자에게 보여준다. `docs/GUIDEBOOK.md`·`docs/FIGMA-GUIDEBOOK.md`에 같은 내용이 요약돼 있으면 그것도 목록에 포함한다.
3. **각 섹션 수정안을 개별 승인.** 한 번에 전부가 아니라 섹션 단위로. 어느 하나가 반려되면 그 이전 승인분은 커밋하지 않는다.
4. **`docs/design-system-rule/CHANGELOG.md` 에 한 줄 기록.** 뭘 바꿨고 왜 바꿨는지.
5. **`npm run rulebook:verify` 로 정합성 확인.** `tokens/design-tokens.json` 이 부트스트랩 된 이후에만 유효.

사용자가 직접 편집할 때도 4·5 를 지키면 룰북과 현실 사이의 드리프트를 조기에 잡을 수 있다.
