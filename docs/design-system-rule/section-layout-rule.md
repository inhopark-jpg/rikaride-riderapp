# 섹션 레이아웃 규칙

> **다루는 것** — Figma 페이지 안에서 컴포넌트와 화면을 Section 으로 정리하는 법(컴포넌트 레이아웃 / 페이지 레이아웃), 그리고 이미 정리된 섹션 구조를 읽어서 레이어·빌딩블록·공유 범위를 판별하는 법.
> **관련 룰북** — `component-structure-rule.md` (레이어 판별 §1, 빌딩블록·스코프 플래그 §2, 네이밍 §3, 어느 Figma 페이지에 둘지 §4), `design-to-dev-rule.md` (Figma 이름이 정본 §1)
> **소비 제약** — 없음. 섹션은 캔버스 정리 수단이며 코드로 옮겨지지 않는다.

> 이 문서는 Figma MCP 로 연결된 파일의 섹션 구조를 해석하거나, 컴포넌트·화면을 새로 섹션에 배치할 때 참고하는 규칙 문서입니다. `component-structure-rule.md` §4 가 "어느 Figma 페이지에 둘 것인가"를 정한다면, 이 문서는 "그 페이지 안에서 섹션을 어떻게 짤 것인가"를 정합니다.
>
> **중요 — 예시 이름은 규칙이 아닙니다.** `button`, `btn-primary`, `map-overlay`, `Home` 같은 이름은 예시 프로젝트(Rider-App)에서 가져온 것입니다. 적용할 것은 섹션 종류, 중첩 순서, 배치 판정 기준이며, 실제 파일의 이름에 이 로직을 대입해서 판단합니다.

---

## 0. 체크리스트

섹션을 만들거나 고치기 전:

1. 이 Figma 페이지가 **컴포넌트 레이아웃**(패밀리 페이지, Foundations)인가 **페이지 레이아웃**(feature 화면)인가? → §3 / §4
2. 섹션 하나에 **주제 컴포넌트(또는 화면) 하나**만 들어가는가? → §2
3. 섹션 이름이 규칙대로인가 — template·pattern 섹션은 컴포넌트 이름과 **완전히 같게**, 빌딩블록 섹션은 `building-block`, sub-group 은 이름 없음 → §2
4. 각 빌딩블록이 "누가 쓰는가"에 맞는 위치에 있는가? → §2 「빌딩블록 배치」
5. 보기 편하게 하려고 섹션을 추가하지 않았는가 (가시성용 배경 등) → §7

기존 섹션을 읽을 때는 §5 절차를 따른다.

## 1. 섹션 종류

| 종류 | 이름 | 담는 것 |
|---|---|---|
| **최상위 그룹** | 컴포넌트 레이아웃: 패밀리명 (`button`) / 페이지 레이아웃: 흐름 이름 (`Home`) | sub-group 들 |
| **sub-group** | 없음 (빈 문자열) | 빌딩블록을 공유하는 템플릿·패턴 묶음(§3) 또는 로컬 컴포넌트를 공유하는 페이지 묶음(§4) |
| **template 섹션** | 그 템플릿의 컴포넌트 이름 (`btn-primary`) | 템플릿 컴포넌트 1개 + 그 템플릿의 pattern 섹션 + 그 템플릿 전용 빌딩블록 |
| **pattern 섹션** | 그 패턴의 컴포넌트 이름 (`btn-ghost/pattern-go-back`) | 패턴 컴포넌트 1개 + 그 패턴 전용 빌딩블록 |
| **page 섹션** | 화면 이름 (`page A`, `sub page A-1`) | 화면 frame + 하위 page 섹션 + 그 범위의 빌딩블록 |
| **building-block 섹션** | `building-block` (고정) | 빌딩블록 컴포넌트 1개 + 그 빌딩블록의 빌딩블록. 또는 building-block 섹션 여러 개를 묶는 줄 |
| **메모 섹션** | 자유 (`적용 예시` 등) | 사용 예시·설명. **배경 투명** — 구조 판정에서 제외 |

- **용어 주의 — "페이지"는 두 가지를 가리킬 수 있다.** 이 문서에서 그냥 "페이지"(page 섹션, 페이지 레이아웃, sub page)라고 하면 **앱·웹사이트의 화면 페이지**다. Figma 좌측 패널의 페이지는 항상 **"Figma 페이지"**라고 적어 구분한다.
- 섹션이 아닌 노드는 그 섹션의 내용이고, 구조 판정에는 그 섹션의 **주제**(컴포넌트 또는 화면)만 쓴다. 주석(이름표·앵커·브래킷)과 메모 frame 은 쓰지 않는다.
- 어느 노드가 주제인지는 맥락으로 판단한다 (예: `btn-primary` 섹션 안의 `btn-primary`). 판단이 서지 않으면 보고한다.
- 이 표의 "빌딩블록"은 `component-structure-rule.md` §2 의 빌딩블록(이름 `.` 접두사)이다. 단 페이지 레이아웃의 building-block 섹션은 §4 의 정의를 따른다.
- **빌딩블록은 레이어가 아니라 플래그다** (`component-structure-rule.md` §2). 섹션 이름 `building-block` 은 "재료이고, 놓인 위치가 사용 범위"라는 것만 뜻한다. 섹션 안의 구성은 주제의 레이어를 따른다 — 빌딩블록인 템플릿도 template 섹션처럼 pattern 줄을 가질 수 있다 (§3).

## 2. 공통 규칙

### 쓰는 쪽이 위, 재료가 아래

섹션의 위아래와 중첩은 곧 **사용 관계**다. 어떤 컴포넌트를 쓰는 것(패턴, 화면)은 위에, 그 컴포넌트가 쓰는 재료(빌딩블록)는 아래·안쪽에 둔다.

### 섹션 하나 = 주제 하나

template·pattern·building-block 섹션은 **주제 컴포넌트를 정확히 하나** 담는다. page 섹션은 **화면 하나**(와 그 화면의 상태 변형 frame)를 담는다. 주제 컴포넌트가 둘이면 섹션을 나눈다. 주제를 고르는 법은 §1 을 따른다 — 주석처럼 구조와 무관한 컴포넌트는 개수에 넣지 않는다. (예외: §3 「예외 — 아이콘 글리프」)

### 이름

| 섹션 | 이름 규칙 |
|---|---|
| template · pattern | 담긴 컴포넌트(또는 컴포넌트 셋)의 이름과 **글자 하나까지 같게** |
| building-block | 항상 `building-block`. 담긴 컴포넌트 이름을 쓰지 않는다 |
| sub-group | 이름 없음. 이름 없는 섹션은 sub-group 에만 쓴다 |
| 최상위 그룹 | 패밀리명(소문자) 또는 흐름 이름 |
| page | 화면 이름 |

### 빌딩블록 배치

빌딩블록 섹션의 위치는 **그 빌딩블록을 누가 쓰는가**로 정해진다. 위에서부터 처음 해당되는 것을 적용한다.

패턴은 빌딩블록이어도 이 배치 규칙 대신 §3 대로 자기 템플릿 섹션의 pattern 줄에 둔다. 템플릿의 사용처를 셀 때 자기 패턴은 빼고, 그 패턴들의 사용처를 템플릿의 사용처로 본다.

1. **다른 빌딩블록이 쓰면** → 그 빌딩블록의 building-block 섹션 **안**에 중첩한다 (재료의 재료). 템플릿도 함께 직접 쓰더라도 중첩을 우선한다.
2. **그 외** → 쓰는 것들을 **모두 포함하는 가장 안쪽 섹션의 맨 아래**에 둔다.
   - 템플릿 하나만 씀 → 그 template 섹션 맨 아래
   - 같은 sub-group 의 템플릿 여럿이 씀 → sub-group 맨 아래
   - 화면 하나만 씀 → 그 page 섹션 맨 아래 / 여러 화면이 씀 → 그 화면들을 모두 포함하는 page 섹션 또는 sub-group 맨 아래
3. **같은 Figma 페이지 안에 쓰는 곳이 없으면**(다른 Figma 페이지에서만 쓰임) → 독립 sub-group 으로 둔다.

"쓴다" = 컴포넌트 정의 안에 그 컴포넌트의 인스턴스가 들어 있다. 메모 섹션·예시 frame 안의 인스턴스는 "쓴다"로 치지 않는다. 다른 Figma 페이지의 컴포넌트(아이콘, 다른 패밀리의 템플릿)를 쓰는 것은 배치에 영향을 주지 않는다.

### 배경색

최상위 그룹은 **투명**, 그 안쪽부터 깊이마다 **흰색 `#FFFFFF` → 밝은 회색 `#F2F2F2` → 어두운 회색 `#E6E6E6` → 밝은 회색 → …** 을 번갈아 칠한다. 메모 섹션은 투명으로 두고 이 순서에서 건너뛴다(메모 안의 섹션은 메모 바깥의 순서를 잇는다). 이 값은 디자인 토큰이 아니라 캔버스 정리용 고정값이다.

### 간격

| 항목 | 값 |
|---|---|
| 섹션 안쪽 여백 (padding) | 100 |
| 같은 줄 형제 섹션 사이 | 100 |
| 컴포넌트 레이아웃 — 위아래 띠 사이 (§3) | 200 |
| 페이지 레이아웃 — 화면 ↔ 하위 page 줄, 위 ↔ building-block 줄 (§4) | 1000 |
| 페이지 레이아웃 — page sub-group 사이 (세로) | 1000 |

같은 줄의 형제끼리 어떤 순서로 놓을지는 정하지 않는다.

### building-block 섹션의 폭

맨 아래 띠의 building-block 섹션은 **부모 섹션의 안쪽 폭이 더 넓으면 그 폭까지 늘린다.** 컴포넌트 레이아웃·페이지 레이아웃 모두 같다. 같은 띠에 building-block 섹션이 여러 개 나란히 있으면 각자 자기 내용 폭을 유지한다.

## 3. 컴포넌트 레이아웃

패밀리 Figma 페이지와 Foundations Figma 페이지(`component-structure-rule.md` §4)에 적용한다.

```
┌ {패밀리명} (투명) ─────────────────────────────────────────────┐
│ ┌ sub-group ─────────────────────────┐ ┌ sub-group ────────┐  │
│ │ ┌ {템플릿} ─┐ ┌ {템플릿} ──────────┐ │ │ ┌ {복합 템플릿} ┐ │  │
│ │ │           │ │ [pattern][pattern] │ │ │ │               │ │  │
│ │ │ 템플릿    │ │      ↕ 200         │ │ │ └───────────────┘ │  │
│ │ │ + 주석    │ │ 템플릿 + 주석·메모  │ │ └───────────────────┘  │
│ │ │ ↕ 200     │ │      ↕ 200         │ │      ←100→             │
│ │ │ [b-b]     │ │ [building-block]   │ │                        │
│ │ └───────────┘ └────────────────────┘ │                        │
│ │              ↕ 200                   │                        │
│ │ [building-block ── 공유 스켈레톤 ──] │                        │
│ └──────────────────────────────────────┘                        │
└─────────────────────────────────────────────────────────────────┘
```

### 최상위 그룹과 sub-group

- 패밀리 섹션 하나에 sub-group 들을 **가로 한 줄**로 놓는다 (간격 100).
- **sub-group = 같은 빌딩블록을 공유하는 템플릿·패턴의 묶음.** 공유 관계로 이어진 것끼리 같은 sub-group 에, 이어지지 않은 것은 다른 sub-group 에 둔다.
  - 예: `.skeleton/btn` 을 함께 쓰는 `btn-primary`·`btn-secondary`·`btn-ghost` → 한 sub-group
  - 공유하는 빌딩블록이 없는 템플릿, 복합 템플릿, 템플릿 없이 만든 독립 패턴 → 각자 자기 sub-group
  - 복합 템플릿이 다른 sub-group 의 **템플릿**(퍼블리시되는 컴포넌트)을 쓰는 것은 공유로 치지 않는다. 공유는 빌딩블록(`.` 접두사)에만 해당한다.
- Foundations 처럼 패밀리가 없는 Figma 페이지에도 같은 규칙을 적용한다.

### template 섹션 — 3개 띠 (위 → 아래, 띠 사이 200)

1. **pattern 줄** — 이 템플릿을 고정한 pattern 섹션들을 가로 한 줄로. 패턴이 없으면 이 띠는 없다.
   - 어느 template 섹션에 들어갈지는 패턴 이름의 앞부분이 정한다: `btn-ghost/pattern-go-back` → `btn-ghost` 섹션.
   - 템플릿이 빌딩블록이어도 같다: `.gnb-bar-item/pattern-guide` → `.gnb-bar-item` 이 든 building-block 섹션. 앞부분을 비교할 때 `.` 접두사는 무시한다.
2. **본문** — 템플릿 컴포넌트, 주석, 메모 섹션.
3. **building-block 줄** — 이 템플릿만 쓰는 빌딩블록 (§2 「빌딩블록 배치」).

pattern 섹션도 같은 구조다 — 본문(패턴 컴포넌트) 아래에 그 패턴만 쓰는 빌딩블록.

### building-block 섹션

- 본문에 빌딩블록 컴포넌트 **하나**, 그 아래 띠(200)에 이 빌딩블록이 쓰는 빌딩블록들의 building-block 섹션을 가로 한 줄로 — 재귀 구조.
- 주제가 패턴이 있는 템플릿이면 template 섹션과 같은 3띠(pattern 줄 → 본문 → building-block 줄)를 쓴다. 섹션 이름은 그대로 `building-block`, 그 안의 pattern 섹션 이름은 패턴 컴포넌트 이름이다.
- 폭은 §2 「building-block 섹션의 폭」을 따른다.

### 높이

형제 섹션끼리 높이를 맞추지 않는다. 각 섹션은 자기 내용을 감싼다.

### 예외 — 아이콘 글리프

`icon-frame-*` 이 인스턴스 교체로 받는 개별 아이콘 컴포넌트(`icon-prop-rule.md`)는 수가 많아 하나씩 섹션을 두지 않는다. building-block 줄 안에 **분류별 섹션**으로 묶는다.

- 분류 섹션에는 §2 「섹션 하나 = 주제 하나」와 이름 규칙을 적용하지 않는다. 이름은 분류명(자유)이다.
- 배경·여백·간격·폭 규칙은 그대로 따른다.
- `icon-frame-*` 처럼 아이콘 Figma 페이지에 있는 다른 컴포넌트는 일반 규칙을 따른다.

## 4. 페이지 레이아웃

feature 화면이 있는 Figma 페이지(`component-structure-rule.md` §4 의 Feature Figma 페이지)에 적용한다.

```
┌ {흐름 이름} (투명) ─────────────────────────────────────────────────┐
│ ┌ sub-group ──────────────────────────────────────────────────────┐ │
│ │ ┌ page A ───────────────────────────────┐ ┌ page B ───────────┐ │ │
│ │ │ [화면] ←1000→ [sub page A-1][A-2] …   │ │ [화면] ←1000→ … │ │ │
│ │ │             ↕ 1000                    │ │       ↕ 1000      │ │ │
│ │ │ [building-block 줄]                   │ │ [building-block 줄] │ │ │
│ │ └───────────────────────────────────────┘ └───────────────────┘ │ │
│ │                       ↕ 1000                                     │ │
│ │ [building-block 줄 ── page A·B 공유 ──────────────────────────] │ │
│ └─────────────────────────────────────────────────────────────────┘ │
│                         ↕ 1000                                       │
│ ┌ sub-group ──────────────────────────────────────────────────────┐ │
│ │ …                                                               │ │
└──────────────────────────────────────────────────────────────────────┘
```

### 최상위 그룹과 sub-group

- 흐름(예: 홈, 설정) 하나가 최상위 그룹 하나다.
- sub-group 들을 **세로로** 쌓는다 (간격 1000). 컴포넌트 레이아웃(가로 100)과 다르다.
- **sub-group = 로컬 컴포넌트를 공유하는 최상위 page 섹션들의 묶음.** 공유하는 것이 없으면 다른 sub-group 이다.

### page 섹션 — 2개 띠 (위 → 아래, 띠 사이 1000)

1. **위 띠** — 왼쪽에 이 page 의 화면 frame, 오른쪽으로 1000 띄우고 하위 page 섹션(sub page)들을 가로 한 줄로 (간격 100). 하위 page 섹션도 같은 구조를 재귀로 가진다 (sub page → sub-sub page …).
   - 하위 page = 이 화면에서 진입하는 화면.
2. **building-block 줄** — 이 page 와 그 하위 page 들이 쓰는 로컬 컴포넌트 (§2 「빌딩블록 배치」).

### 페이지 레이아웃의 building-block

- 여기 들어가는 것은 **이 feature 의 화면들이 쓰는 로컬 컴포넌트**(`component-structure-rule.md` §2 스코프 = 전용)다. 자기 Figma 페이지가 따로 배정된 패밀리 컴포넌트(§4 규칙 1·3·4)는 여기 두지 않는다.
- 구조: building-block 줄(섹션 이름 `building-block`) 안에 로컬 컴포넌트마다 building-block 섹션을 하나씩 가로로 놓는다. 각 섹션의 내부는 §3 의 building-block 섹션과 같다.
- 공유 범위가 위치를 정한다: 화면 하나만 쓰면 그 page 섹션, 여러 page 가 쓰면 그들을 모두 포함하는 page 섹션, 최상위 page 여럿이 쓰면 sub-group 맨 아래.

### 높이와 폭

- 같은 줄의 형제 page 섹션은 **높이를 맞춘다** (가장 높은 것 기준). 컴포넌트 레이아웃과 다르다.
- building-block 줄의 폭은 §2 「building-block 섹션의 폭」을 따른다.

## 5. 기존 섹션 읽기 (해석 절차)

이미 정리된 Figma 페이지를 읽고 각 컴포넌트의 레이어·빌딩블록 여부·공유 범위를 판별하는 순서.

1. **레이아웃 종류 판별** — 최상위 그룹 안에 화면 frame 이 있으면 페이지 레이아웃(§4), 컴포넌트 정의가 있으면 컴포넌트 레이아웃(§3).
2. **섹션 종류 판별** — 배경이 투명이면 메모(제외). 이름이 없으면 sub-group. 이름이 `building-block` 이면 building-block 섹션. 그 밖에 이름이 있는 섹션은 컴포넌트 레이아웃이면 template/pattern 섹션, 페이지 레이아웃이면 page 섹션이다.
3. **주제와 레이어** — 섹션의 주제(§1)와 그 레이어(`component-structure-rule.md` §1·§3)를 판단한다. 섹션 이름과 컴포넌트 이름이 다르면 **컴포넌트 이름이 정본**이다 (`design-to-dev-rule.md` §1).
4. **위치에서 정보 읽기** — 섹션 위치가 곧 사용 관계다.
   - template 섹션 맨 아래 building-block → 그 템플릿 전용 재료
   - sub-group 맨 아래 building-block → 그 sub-group 템플릿들의 공유 재료(주로 공유 스켈레톤)
   - building-block 섹션 안의 building-block → 바깥 빌딩블록의 재료
   - building-block 섹션의 pattern 줄 → 그 빌딩블록 템플릿을 고정한 패턴(역시 재료)
   - 같은 sub-group 의 템플릿들 → 같은 스켈레톤을 공유한다
   - 페이지 레이아웃의 building-block → 그 범위 화면들이 쓰는 로컬(전용) 컴포넌트
5. **사용 관계로 확인** — 위치가 말하는 관계가 실제 인스턴스 사용(인스턴스의 main component)과 맞는지 확인한다. 이름이나 위치가 사용 관계와 어긋나면 §7 의 편차다.
6. **편차는 보고만 한다** — 추측해서 섹션을 고치거나, 어긋난 이름에 맞춰 레이어를 판정하지 않는다. 어떤 섹션이 어떤 규칙과 어떻게 어긋나는지 보고한다.

## 6. 다른 룰북과의 관계

- **`component-structure-rule.md` §4** 가 컴포넌트를 어느 **Figma 페이지**에 둘지 정하고, 이 문서가 그 Figma 페이지 안의 **섹션 구성**을 정한다. 패밀리·Foundations Figma 페이지는 §3, Feature Figma 페이지는 §4 를 따른다.
- Feature Figma 페이지의 로컬 컴포넌트는 따로 모아두는 섹션 없이 §4 의 building-block 줄에 사용 범위대로 둔다.
- 섹션 이름과 컴포넌트 이름이 같아야 하므로, 컴포넌트 이름 규칙(`component-structure-rule.md` §3)을 지키면 섹션 이름도 정해진다.

## 7. 자주 발생하는 오류 패턴

| 오류 | 올바른 처리 |
|---|---|
| 섹션 이름과 안의 컴포넌트 이름이 다름 (컴포넌트 이름만 바꾸고 섹션은 그대로 둠 등) | 섹션 이름을 컴포넌트 이름과 같게. 읽을 때는 컴포넌트 이름을 정본으로 보고 불일치를 보고 |
| 작거나 흰 컴포넌트가 안 보여서 배경용 섹션으로 감쌈 | 섹션을 추가하지 않는다. 이름 없는 섹션은 sub-group 으로 읽히므로 구조가 어긋난다. 필요하면 섹션이 아닌 배경 frame 을 컴포넌트 뒤에 둔다 |
| building-block 섹션 이름을 컴포넌트 이름으로 지음 | 항상 `building-block`. 어떤 빌딩블록인지는 안의 컴포넌트 이름이 말해 준다 |
| 공유 빌딩블록이 없는 템플릿·패턴을 한 sub-group 에 모음 | 빌딩블록 공유로 이어진 것끼리만 같은 sub-group. 나머지는 각자 sub-group |
| 한 템플릿만 쓰는 빌딩블록을 sub-group 맨 아래(공유 위치)에 둠 | 그 template 섹션 맨 아래로. 위치가 공유 범위를 뜻한다 |
| 빌딩블록이 쓰는 빌딩블록을 형제로 나란히 둠 | 쓰는 빌딩블록의 building-block 섹션 안에 중첩 |
| 섹션 하나에 주제 컴포넌트 여러 개 | 컴포넌트마다 섹션 하나 || 메모(사용 예시)를 배경 있는 섹션으로 만듦 | 메모 섹션은 배경 투명 — 배경이 있으면 구조 섹션으로 오독된다 |
