# Language 토큰 적용 규칙 (공통 룰북)

> **다루는 것** — `language` 컬렉션 (다국어 i18n 문자열). 토큰명 = 번역 키. 모드 = 언어.
> **관련 룰북** — `typography-token-rule.md` §3 (언어 축, 동기 전환), `color-token-rule.md` §9 (모드 누락 검사 패턴)
> **소비 제약** — 텍스트 노드 / text prop value 에만 적용. CSS 변수가 아닌 별도 i18n 파일 파이프라인.

**이 컬렉션은 엄밀히 말해 "디자인 토큰" 이 아닙니다.** 앱/웹의 다국어 문자열을 관리하기 위한 i18n(국제화) 토큰 컬렉션입니다. 색상·간격 같은 시각 토큰과는 코드 파이프라인이 다릅니다.

> **적용 범위 / 전제**: 새 Figma 파일에 `language` 컬렉션이 있고, 언어별 모드(예: `korean`, `english`) 를 가지며, 각 변수의 값이 언어별 문자열일 때 유효합니다. 이름이 다르면 이 룰북을 적용하지 마세요.

## 0. 체크리스트

1. `language` 컬렉션이 존재하는지 확인한다.
2. 모드가 언어별로 나뉘어 있는지 확인한다 (예: `korean` / `english` / ...).
3. 각 변수의 값이 언어별 문자열 (예: "다음" / "Next") 인지 확인한다.
4. 컴포넌트의 텍스트 노드나 text prop 에 이 컬렉션의 토큰이 참조로 바인딩되어 있는지 확인한다 (하드코딩된 문자열이 아니라).

## 1. 핵심 원칙 — 텍스트 노드 / text prop 에만 적용

**`language` 컬렉션의 토큰은 텍스트 노드 또는 컴포넌트의 text prop value 에만 바인딩됩니다.** 색상, 크기, 배경 등 다른 속성에는 적용할 수 없습니다.

이 제약은 `typeface-semantic` ↔ Text Style, `icon-prop` ↔ `icon-frame-*` 처럼 소비 경로가 지정된 다른 컬렉션들과 같은 패턴입니다.

## 2. 토큰명 = 번역 키 (ID)

이 컬렉션에서는 **토큰명 자체가 번역 키(translation key)** 로 쓰입니다. 값이 아니라 이름이 식별자입니다.

예:

- 토큰명 `action/next`
  - korean 모드 값: `"다음"`
  - english 모드 값: `"Next"`
- 토큰명 `action/confirm`
  - korean 모드 값: `"확인"`
  - english 모드 값: `"Confirm"`

Figma 에서 텍스트 노드에 하드코딩된 문자열을 넣지 않고 이 토큰을 참조로 바인딩합니다. 모드를 바꾸면 그 텍스트 노드의 실제 표시 문자열이 자동으로 바뀝니다 — 디자이너가 언어별 레이아웃(문자 길이 차이 등) 을 Figma 안에서 바로 검토할 수 있습니다.

## 3. 모드 = 언어

각 모드가 한 언어를 나타냅니다. 모드 전환 = 앱의 언어 전환.

**중요 — `typeface-semantic` 과 동기 전환:** `typeface-semantic` 컬렉션도 언어별 모드(브랜드×언어) 를 가지며, 이건 어떤 **폰트** 를 쓸지 결정합니다. `language` 컬렉션은 어떤 **문자열** 을 쓸지 결정합니다. **앱 언어가 바뀌면 두 컬렉션의 모드가 동시에 바뀌어야** 합니다. 하나만 바뀌면 텍스트 내용은 영어인데 폰트는 한글 전용이 적용되는 식으로 어긋납니다.

동기 전환 예:

```
앱 언어: 한국어  →  [data-language="korean"] + [data-typeface="brand-korean"]
앱 언어: 영어    →  [data-language="english"] + [data-typeface="brand-english"]
```

정확한 typeface 모드 이름과 어떤 조합이 유효한지는 `typography-token-rule.md` §3 참고.

## 4. 코드 파이프라인 — CSS 변수가 아닌 i18n 파일

문자열 토큰은 CSS 변수로 방출하지 않습니다. `tokens/build-theme.mjs` 파이프라인과 별개로 취급합니다.

**원칙:**

- `language` 컬렉션은 별도 i18n 파일(예: `tokens/i18n/{언어}.json` 또는 `src/i18n/*.json`) 로 추출
- 앱은 i18n 라이브러리(예: `react-i18next`, `react-intl` 등 — 국제화 문자열 관리를 도와주는 라이브러리 총칭) 로 이 파일을 소비
- 앱의 현재 언어 상태에 따라 라이브러리가 해당 문자열을 반환

구체적인 추출 스크립트, 파일 구조, i18n 라이브러리 선택은 부트스트랩 시 결정합니다. **`design-tokens.json` 안에 담아 CSS 변수로 방출하려고 시도하지 마세요** — 문자열은 CSS 값이 아닙니다.

## 5. 새 문자열 추가

디자이너가 새 UI 문자열을 도입할 때:

1. Figma 의 `language` 컬렉션에 새 변수 생성 (예: `action/save-draft`)
2. 각 언어 모드마다 값을 채운다 ("초안 저장" / "Save draft")
3. 그 문자열이 표시될 텍스트 노드에 이 토큰을 참조로 바인딩

**주의 — 언어 모드가 추가됐을 때:** 새 언어가 추가되면 기존 토큰 전부에도 그 언어의 값을 채워야 합니다. 값이 빈 채로 두면 그 언어에서 빈 문자열로 표시됩니다. 이 상황은 `sync-tokens` 스킬이 감지해서 보고합니다 (`color-token-rule.md` §9 의 모드 누락 검사와 같은 패턴).

## 6. 오류 패턴

| 오류 | 올바른 처리 |
|---|---|
| 텍스트 노드에 문자열을 하드코딩 | `language` 컬렉션의 해당 토큰을 참조로 바인딩 |
| language 토큰을 색상·크기 등 다른 속성에 적용 | 텍스트 노드/text prop 에만 가능 |
| 앱 언어 전환 시 language 모드만 바꾸고 typeface-semantic 은 안 바꿈 | 두 컬렉션의 모드를 동시에 전환 |
| 새 토큰을 추가하면서 일부 언어 모드에 값을 안 넣음 | 모든 언어 모드에 값을 채운다 |
| `language` 토큰을 `design-tokens.json` 에서 CSS 변수로 뽑으려고 시도 | 별도 i18n 파일 파이프라인으로 처리 |

## 7. 치트시트

| 하고 싶은 것 | 참고할 곳 |
|---|---|
| Figma 텍스트 노드에 다국어 문자열 넣기 | `language` 컬렉션의 해당 토큰을 참조로 바인딩 |
| 새 UI 문자열 도입 | `language` 컬렉션에 새 변수 + 모든 언어 값 채움 |
| 앱 언어 전환 로직 | language 모드 + typeface-semantic 모드 **동시** 전환 |
| 언어별 폰트가 궁금하다 | `typography-token-rule.md` §3 (typeface-semantic 언어 축) |
| 실제 코드 소비 방식 | 부트스트랩 시 결정 — 원칙은 별도 i18n 파일로 추출 후 i18n 라이브러리로 소비 |
