# Language 변수 적용 규칙

> **다루는 것** — `language` 컬렉션 (다국어 i18n 문자열). 변수 하나 = 번역 항목 하나. 코드의 번역 키는 변수명 끝의 6자 ID. 모드 = 언어.
> **관련 룰북** — `typography-token-rule.md` §3 (언어 축, 동기 전환), `color-token-rule.md` §9 (모드 누락 검사 패턴)
> **소비 제약** — 텍스트 노드 / text prop value 에만 적용. CSS 변수가 아닌 별도 i18n 파일 파이프라인.

**이 컬렉션은 "디자인 토큰" 이 아닙니다.** 서버에서 받지 않는, 앱/웹에 하드코딩되는 다국어 문자열을 관리하기 위한 i18n(국제화) 문자열 컬렉션입니다. 색상·간격 같은 시각 토큰과는 코드 파이프라인이 다릅니다.

> **적용 범위 / 전제**: 새 Figma 파일에 `language` 컬렉션이 있고, 언어별 모드(예: `Korean`, `English`) 를 가지며, 각 변수의 값이 언어별 문자열일 때 유효합니다. 이름이 다르면 이 룰북을 적용하지 마세요.

## 0. 체크리스트

1. `language` 컬렉션이 존재하는지 확인한다.
2. 모드가 언어별로 나뉘어 있는지 확인한다 (예: `Korean` / `English` / ...).
3. 각 변수의 값이 언어별 문자열 (예: "다음" / "Next") 인지 확인한다.
4. 컴포넌트의 텍스트 노드나 text prop 에 이 컬렉션의 변수가 참조로 바인딩되어 있는지 확인한다 (하드코딩된 문자열이 아니라). 번역 테이블은 제외한다 (§8).
5. 미번역 표시(`--`) 나 빈 값이 남은 모드가 없는지 확인한다.

## 1. 핵심 원칙 — 텍스트 노드 / text prop 에만 적용

**`language` 컬렉션의 변수는 텍스트 노드 또는 컴포넌트의 text prop value 에만 바인딩됩니다.** 색상, 크기, 배경 등 다른 속성에는 적용할 수 없습니다.

이 제약은 `typeface-semantic` ↔ Text Style, `icon-frame` 컬렉션 ↔ `icon-frame-*` 컴포넌트 처럼 소비 경로가 지정된 다른 컬렉션들과 같은 패턴입니다.

## 2. 변수 이름 — `{섹션 경로}/{레이어}/{6자 ID}`

변수 이름은 사람도 Claude 도 짓지 않습니다. 변수를 만드는 전용 도구가 다음 형식으로 붙입니다.

```
{가장 가까운 섹션들 (최대 3단계)}/{섹션이 아닌 첫 레이어}/{6자 무작위 ID}
```

예: `section-section-2/layer-frame-3/jpb5aj`

- **앞부분(경로)** 은 그 텍스트가 놓인 섹션 구조에서 만들어집니다. 섹션을 정리하면 바뀔 수 있으므로 식별자로 쓰지 않습니다.
- **끝의 6자 ID** 는 한 번 붙으면 바뀌지 않습니다. **코드의 번역 키는 이 ID 입니다** (`…/jpb5aj` → `jpb5aj`).

값이 아니라 이름(의 ID)이 식별자입니다. 같은 ID 의 변수는 모드마다 언어별 값을 가집니다.

- `…/jpb5aj`
  - Korean 모드 값: `"텍스트 노드"`
  - English 모드 값: `"text node"`

Figma 에서 텍스트 노드에 하드코딩된 문자열을 넣지 않고 이 변수를 참조로 바인딩합니다. 모드를 바꾸면 그 텍스트 노드의 실제 표시 문자열이 자동으로 바뀝니다 — 디자이너가 언어별 레이아웃(문자 길이 차이 등) 을 Figma 안에서 바로 검토할 수 있습니다.

## 3. 모드 = 언어

각 모드가 한 언어를 나타냅니다. 모드 전환 = 앱의 언어 전환.

**중요 — `typeface-semantic` 과 동기 전환:** `typeface-semantic` 컬렉션도 언어별 모드(브랜드×언어) 를 가지며, 이건 어떤 **폰트** 를 쓸지 결정합니다. `language` 컬렉션은 어떤 **문자열** 을 쓸지 결정합니다. **앱 언어가 바뀌면 두 컬렉션의 모드가 동시에 바뀌어야** 합니다. 하나만 바뀌면 텍스트 내용은 영어인데 폰트는 한글 전용이 적용되는 식으로 어긋납니다.

동기 전환 예:

```
앱 언어: 한국어  →  [data-language="korean"] + [data-typeface="brand-korean"]
앱 언어: 영어    →  [data-language="english"] + [data-typeface="brand-english"]
```

정확한 typeface 모드 이름과 어떤 조합이 유효한지는 `typography-token-rule.md` §3 참고.

## 4. 코드 파이프라인 — CSS 변수가 아닌 i18n 파일

문자열 변수는 CSS 변수로 방출하지 않습니다. `tokens/build-theme.mjs` 파이프라인과 별개로 취급합니다.

**원칙:**

- **추출 원본** — `figma-dump.js` 로 받은 `language` 컬렉션 덤프
- **파일 형식** — 언어(모드) 하나에 파일 하나. 키 = 변수명 끝의 6자 ID (§2), 값 = 그 모드의 문자열
- **미번역 처리** — 값이 `--` 이거나 비어 있으면 문자열로 내보내지 않고 누락으로 보고한다
- **추출 스크립트** — `tokens/extract/to-i18n.mjs` (`npm run i18n:extract`). `to-dtcg.mjs` 는 `language` 컬렉션을 건너뛴다
- **출력** — `src/i18n/locales/{언어}.json` 과 언어 목록·기본 언어를 담은 `src/i18n/locales/index.json`. Figma 에 모드가 추가되면 파일도 추가된다
- **소비** — `src/i18n/index.ts` 의 `t(id, 언어)`. 외부 i18n 라이브러리는 쓰지 않는다. 현재 언어에 값이 없으면 기본 언어 문자열로 대체한다

**`design-tokens.json` 안에 담아 CSS 변수로 방출하려고 시도하지 마세요** — 문자열은 CSS 값이 아닙니다.

## 5. 새 문자열 추가

**변수 생성과 텍스트 노드 연결은 사람이 전용 도구로 합니다.** 도구가 이름(§2)과 함께 자기 내부 데이터를 기록하므로, 다른 경로로 만들면 그 데이터가 빠집니다. Claude 는 `use_figma` 로 `language` 변수를 만들거나 텍스트 노드에 연결하지 않습니다.

Claude 가 하는 일:

1. 바인딩되지 않은 하드코딩 텍스트를 찾아 노드 이름·nodeId·문자열로 보고한다
2. 각 언어 모드의 번역을 제안한다
3. 이미 있는 변수의 미번역(`--`) 값이나 틀린 값을 승인받아 채우거나 고친다 — 값 수정은 이름·연결을 건드리지 않으므로 가능하다

**주의 — 언어 모드가 추가됐을 때:** 새 언어가 추가되면 기존 변수 전부에도 그 언어의 값을 채워야 합니다. 값을 `--` 나 빈 채로 두면 그 언어에서 그대로 표시되거나 빈 문자열이 됩니다. 덤프에서 `--`·빈 값을 모드별로 세어 보고합니다 (`color-token-rule.md` §9 의 모드 누락 검사와 같은 패턴).

## 6. 오류 패턴

| 오류 | 올바른 처리 |
|---|---|
| 텍스트 노드에 문자열을 하드코딩 | `language` 컬렉션의 해당 변수를 참조로 바인딩 |
| language 변수를 색상·크기 등 다른 속성에 적용 | 텍스트 노드/text prop 에만 가능 |
| 앱 언어 전환 시 language 모드만 바꾸고 typeface-semantic 은 안 바꿈 | 두 컬렉션의 모드를 동시에 전환 |
| 새 변수를 추가하면서 일부 언어 모드에 값을 안 넣음 (`--` 로 남김) | 모든 언어 모드에 값을 채운다 |
| `language` 변수를 `design-tokens.json` 에서 CSS 변수로 뽑으려고 시도 | 별도 i18n 파일 파이프라인으로 처리 |
| Claude 가 `use_figma` 로 language 변수를 생성하거나 텍스트 노드에 연결 | 사람이 전용 도구로 한다 (§5). Claude 는 찾기·번역 제안·기존 값 수정만 |
| 변수 이름을 지어내거나 바꿈 | 이름은 생성 도구가 관리한다 (§2) |
| 번역 테이블 행을 사용처로 세거나, 테이블 헤더를 하드코딩 텍스트로 판정 | 번역 테이블은 검사에서 제외 (§8) |
| 코드에서 변수 전체 경로를 번역 키로 사용 | 끝의 6자 ID 만 키로 쓴다 (§2) |

## 7. 치트시트

| 하고 싶은 것 | 참고할 곳 |
|---|---|
| Figma 텍스트 노드에 다국어 문자열 넣기 | `language` 컬렉션의 해당 변수를 참조로 바인딩 |
| 새 UI 문자열 도입 | 사람이 전용 도구로 변수 생성·연결. Claude 는 하드코딩 텍스트 보고와 번역 제안 (§5) |
| 앱 언어 전환 로직 | language 모드 + typeface-semantic 모드 **동시** 전환 |
| 언어별 폰트가 궁금하다 | `typography-token-rule.md` §3 (typeface-semantic 언어 축) |
| 실제 코드 소비 방식 | `figma-dump.js` 덤프 → `npm run i18n:extract` → `src/i18n/locales/{언어}.json`(키 = 6자 ID) → `t(id, 언어)` (§4) |
| 하드코딩 텍스트 검사에서 빼야 할 것 | 번역 테이블 (§8) |

## 8. 번역 테이블과 미번역 표시

**번역 테이블** — 화면 옆에 붙여 두는 `i18n-table` 인스턴스입니다. 안쪽 `i18n-row` 행의 텍스트는 원본 화면의 텍스트와 **같은 변수에 바인딩된 복사본**이고, 열은 언어 모드입니다.

- 번역 테이블 안의 텍스트는 사용처가 아닙니다. 변수가 어디에 쓰이는지 셀 때 제외합니다.
- 테이블 헤더 텍스트(열 이름 등)는 바인딩하지 않는 것이 정상입니다. 하드코딩 텍스트로 판정하지 않습니다.

**미번역 표시** — 아직 번역하지 않은 모드의 값은 `--` 입니다. 빈 값과 같은 "누락" 으로 취급합니다 (§0 항목 5, §4).

**언어별 레이아웃 확인** — 섹션이나 페이지 단위로 `language` 모드를 바꿔 가며 레이아웃이 깨지지 않는지 봅니다. 모드는 서브트리 단위로 지역 오버라이드되므로, 화면 하나만 다른 언어로 바꿔 나란히 비교할 수 있습니다.
