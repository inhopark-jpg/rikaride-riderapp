# 주석 규칙

> **다루는 것** — Figma 캔버스에 다는 주석: variant 브래킷, 주소(`address-platter`·`.address-anchor`), 레이어 주석(annotation), 컴포넌트 주석(spec), 주석 섹션. 각각 무엇을 설명할 때 쓰고 어디에 두는지.
> **관련 룰북** — `section-layout-rule.md` (주석은 구조 판정에서 제외 §1, 섹션 배경·간격 §2), `component-structure-rule.md` (variant 속성과 타입 분화 §3)
> **소비 제약** — 없음. 주석은 코드로 옮겨지지 않는다.

> 이 문서는 컴포넌트·화면을 사람이 읽기 쉽게 문서화하는 방법을 정한다. 섹션을 어떻게 짤지는 `section-layout-rule.md` 가 정하고, 이 문서는 그 섹션 안에 붙는 설명을 다룬다.
>
> **예시 이름은 규칙이 아니다.** `.gnb-bar-item`, `liquid-glass` 같은 이름은 예시 프로젝트(Rider-App)에서 가져왔다.

---

## 0. 체크리스트

1. variant 가 둘 이상인 컴포넌트 셋에 브래킷이 있는가 — 위(X축)와 왼쪽(Y축)에만 → §2
2. 브래킷 라벨이 `{속성}:` 과 `{값}` 두 줄인가 → §2
3. 섹션의 주제(컴포넌트·화면) 마다 `address-platter` 와 `.address-anchor` 가 있고, anchor 텍스트가 주제 이름과 같은가 → §3
4. 설명이 대상에 맞는 도구로 달렸는가 — 레이어 하나는 annotation, 컴포넌트 전체는 spec, 예시·그림은 주석 섹션 → §1
5. 주석 섹션이 fill 없음 + dashed stroke 인가 → §6

---

## 1. 주석 종류

| 설명할 것 | 도구 | 위치 |
|---|---|---|
| variant 가 어느 속성 값인지 | `section-indicator` 브래킷 | 컴포넌트 셋의 위·왼쪽 (§2) |
| 이 UI 가 무엇이고 이름이 무엇인지 | `address-platter` + `.address-anchor` | 가리키는 UI 근처, 같은 섹션 (§3) |
| 컴포넌트 안 특정 레이어 | Figma annotation | 그 레이어 (§4) |
| 컴포넌트 전체 (용도, 속성 사이 관계, 사용 규칙) | Figma spec | 주제 옆, 같은 섹션 (§5) |
| 적용 예시, 그림이 필요한 설명 | 주석 섹션 | 주제 옆, 같은 섹션 (§6) |

- 모든 주석은 구조 판정에 쓰지 않는다 (`section-layout-rule.md` §1). 섹션의 주제 개수에 넣지 않고, 빌딩블록 배치 대상도 아니다.
- `section-indicator` 와 `address-platter` 는 디자이너 주석용 컴포넌트다. 실제 UI 에 쓰지 않는다.
- 설명을 text 노드로 캔버스에 직접 쓰지 않는다. 위 도구 중 하나를 쓴다.

---

## 2. variant 브래킷

컴포넌트 셋의 variant 를 행·열 grid 로 놓고, 각 속성 값이 어느 행·열인지 `section-indicator` 브래킷으로 표시한다.

### 축

- **X축 = 셋 위쪽**, 브래킷 `bracket-direction=bottom`. **Y축 = 셋 왼쪽**, 브래킷 `bracket-direction=right`.
- 셋의 **아래·오른쪽에는 브래킷을 두지 않는다.** 아래는 다음 섹션·주석과, 오른쪽은 이웃 셋과 혼동된다.
- 속성 하나는 한 축에만 놓는다. 나란히 비교해서 보고 싶은 값들이 한 줄에 오도록 고른다. 판단이 서지 않으면 값이 많은 속성을 X축에 둔다.
- 한 축에 속성이 여럿이면 **덜 자주 바뀌는 속성이 바깥**(셋에서 먼 쪽)이다. 바깥 브래킷은 안쪽 그룹 전체를 덮는다.
  - 예: `.gnb-bar-item` 의 X축 — 바깥 `direction`, 안쪽 `state`.
- 값이 하나뿐인 속성은 브래킷을 달지 않는다.

### 라벨

- `{속성}:` 줄바꿈 `{값}` 의 **두 줄**. 한 줄로 쓰면 이웃 라벨과 겹친다.
- 속성명과 값은 Figma 에 적힌 그대로 쓴다. 번역하거나 줄이지 않는다.
- 브래킷 하나 = 값 하나. 그 값을 가진 variant 전부를 덮는다.

### 배치

- grid: 열 폭은 그 열 variant 의 최대 폭, 행 높이는 그 행의 최대 높이. variant 는 cell 가운데. 없는 조합은 빈 cell 로 둔다.
- 기본 간격 — 사람이 읽기 편하면 벗어나도 된다:

| 항목 | 기본값 |
|---|---|
| 셋 안쪽 여백 | 20 |
| cell 사이 | 가장 안쪽 40, 한 단계 바깥마다 +40 |
| 브래킷 길이 | 덮는 cell 보다 양쪽 8 길게 |
| 브래킷 위치 | 셋 가장자리에서 20, 바깥 단계는 안쪽 브래킷 바로 바깥 8 |

- **셋 테두리는 Figma 기본 컴포넌트 셋 테두리(보라 점선)를 유지한다.** 지우지 않는다. 스크립트로 셋을 만들면 빠지므로 직접 넣는다 — stroke `#8A38F5`, 두께 1, dash 10 / gap 5, INSIDE, radius 5 (토큰이 아니라 캔버스 정리용 고정값).

- **겹치지 않는 것이 숫자보다 우선이다.** 라벨이 cell 보다 길면 cell 간격을 넓힌다. 다른 주석(`address-platter` 등)과도 겹치지 않게 한다 — 겉 크기가 아니라 실제로 그려지는 영역 기준.
- 브래킷은 셋과 같은 부모(섹션)에 둔다. 한 섹션에 셋이 여럿이면 각 브래킷은 자기 셋에 가장 가깝게 둔다.

## 3. 주소 — `address-platter` · `.address-anchor`

### `address-platter`

`.address-anchor` 를 담는 판. variant 로 가리키는 UI 의 종류를 표시한다.

| variant | 가리키는 것 |
|---|---|
| `component=true` | 컴포넌트 |
| `page=true` | 화면 페이지 |
| `page=true, overlay=true` | bottom sheet·dialog 처럼 화면 위에 뜨는 요소 |
| `section=true` | 섹션 자체 (패밀리·흐름 같은 묶음) |

- 가리키는 UI 근처, 같은 섹션 안에 둔다.
- 보통 섹션 하나에 하나지만, 한 섹션에 주소를 가질 UI 가 여럿이면 여럿 둔다.

### `.address-anchor`

이 UI 의 주소. 다른 곳에서 이 UI 를 가리킬 때 쓴다.

- platter 안(판의 아래 칸)에 `.address-anchor` **메인 컴포넌트**를 만들어 둔다. UI 하나에 하나.
- anchor 안 텍스트 노드에 **가리키는 UI 의 이름을 글자 하나까지 같게** 적는다 (컴포넌트 이름, 화면 이름). UI 이름이 바뀌면 같이 바꾼다.
- 다른 곳에서 이 UI 를 가리킬 때는 이 anchor 의 **인스턴스**를 놓는다. 디자이너가 인스턴스에서 go to main component 로 원본과 그 사양서로 이동할 수 있다.
  - 예: "클릭하면 설정 화면으로 이동: [설정 화면 anchor 인스턴스]"
- 새 UI 의 anchor 는 기존 anchor 를 복제해 **새 메인 컴포넌트**로 만든다. 다른 UI 의 anchor 인스턴스를 놓으면 그 UI 를 가리키게 된다.
- 레이어 이름은 모두 `.address-anchor` 다. `.` 접두사가 있지만 빌딩블록이 아니라 주석이다 — 섹션 주제·빌딩블록 배치 판정에 쓰지 않는다.

---

## 4. 레이어 주석 — annotation

컴포넌트 안 **특정 레이어**에 대한 설명은 Figma annotation 으로 그 레이어에 단다.

- 카테고리는 넣지 않는다.
- 브래킷 라벨 레이어에 달아 특정 variant 값을 설명해도 된다 (예: `liquid-glass: false` → "false 일 때 …").
- 컴포넌트 전체에 해당하는 내용은 annotation 이 아니라 spec 에 쓴다 (§5).

---

## 5. 컴포넌트 주석 — spec

컴포넌트 **전체**에 대한 설명(용도, 속성 사이 관계, 사용 규칙)은 Figma spec 으로 쓴다.

- **주제 요소 옆, 같은 섹션 안**에 둔다.
- 주석 섹션(§6) 안의 예시를 길게 설명할 때는 그 주석 섹션 안에 둔다.

---

## 6. 주석 섹션

적용 예시나 그림이 필요한 설명은 주석 섹션으로 묶는다.

- 주제 옆, 같은 섹션 안에 둔다. 이름은 자유 (`적용 예시` 등).
- 모양 (토큰이 아니라 캔버스 정리용 고정값):

| 항목 | 값 |
|---|---|
| fill | 없음 |
| stroke | `#000000`, 두께 2, dash 8 / gap 8, OUTSIDE |

- 섹션 배경 번갈이와 간격, 안의 인스턴스를 "쓴다"로 치지 않는 것은 `section-layout-rule.md` §2 를 따른다.

---

## 7. 자주 발생하는 오류 패턴

| 오류 | 올바른 처리 |
|---|---|
| 브래킷을 셋 아래·오른쪽에 둠 | 위(X축)·왼쪽(Y축)에만 |
| 라벨을 `속성: 값` 한 줄로 씀 → 이웃 라벨과 겹침 | `{속성}:` 줄바꿈 `{값}` |
| 겉 크기만 보고 배치해 platter 의 아래 칸을 브래킷이 덮음 | 실제로 그려지는 영역 기준으로 겹침 확인 |
| platter 만 두고 anchor 를 빠뜨림 | 주소를 가질 UI 마다 platter + anchor |
| 새 UI 에 다른 UI 의 anchor 인스턴스를 놓음 | 복제해서 새 메인 컴포넌트로. 인스턴스는 가리키는 곳에서만 |
| anchor 텍스트를 UI 이름 변경 뒤 그대로 둠 | UI 이름과 글자 하나까지 같게 |
| 컴포넌트 전체 설명을 annotation 으로 여러 레이어에 나눠 담 | spec 하나로 |
| 주석 섹션에 배경을 칠함 | fill 없음 + dashed stroke — 배경이 있으면 구조 섹션으로 오독된다 |
